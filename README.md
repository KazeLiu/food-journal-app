# AI 饮食热量与体重记录 APP

轻量级 Android 私人记录工具：像聊天一样说一句吃了什么，由 AI 估算热量并保存；AI 不可用时也能手动记，恢复可用后自动补充缺失的热量。

## 已确认的产品决定

1. Flutter / Dart，Android 优先；SQLite 保存本地数据，不设账户和自有服务器。
2. 底部三个入口：AI 教练、日历 / 我的记录、我的。聊天持续保留，不按天新建会话；允许连续发送，前台按队列逐条处理。
3. 支持文字、拍照、相册；一条消息最多 3 张图片。
4. 图片只用于当前识别。结果与相关记录保存成功后删除 APP 临时副本，不长期保存照片，不删除相册原图。
5. 饮食和体重均支持聊天纠正、直接编辑和删除；支持离线手动新增。
6. AI 仅支持 Responses API，使用一组 Base URL / API Key。拉取模型列表，分别配置文字主模型、文字兜底模型、图片主模型、图片兜底模型。
7. 每次 AI 请求只走对应的主备链：主模型一次，失败后兜底一次。全部失败就明确显示失败，并提供手动记录入口。
8. 手动饮食的热量可以留空，空值表示“待估算”，不是 0 kcal。
9. 下次前台正常使用 AI 成功后，自动尝试估算已有空热量；只更新原记录中的空值，不覆盖已有热量，不在后台定时请求。
10. “已记录 / 已修改”只能出现在本地保存成功后；删除聊天不连带删除饮食或体重。
11. 日合计只包含已记录且已有热量的食物。存在空值时同时显示待估算数量。
12. 不设热量目标、超标提醒、BMI、减肥计划、趋势预测、宏量营养素追踪、社交或云同步。

## 实现方向

客户端负责事实保存、记录定位、去重、汇总和成功回执；AI 负责理解意图、识别食物和提出结构化操作。AI 不直接访问数据库，也不能靠一句自然语言宣布保存成功。

优先完成“手动记录可离线使用 → 文字聊天可靠保存 → 图片识别 → 自动补算与备份”的完整路径，不先搭建复杂的 AI 平台。

## 文档默认值

V1 的实现默认值：备份恢复采用整库替换而非合并；备份不携带 AI 连接配置和 Key；图片使用 JPEG 临时副本；先做浅色主题；AI 输出采用文本 JSON 协议，不强制依赖原生工具调用。

这些是实现选择，不增加新的产品目标。发现实际服务或设备不满足依赖要求时，应针对该事实调整方案并同步相关文档，不悄悄扩大范围。
