# 06 开发计划与验收

## 1. 当前交付和边界

本轮交付完整开发文档、参考设计清单和待确认事项，提交指定 GitHub 仓库；没有 Flutter 工程、APK、真实模型结果或设备验收。

用户要求不再被提问，冲突集中在 09 的 D01–D03，不等待答复；文档按注明的暂定值保持一致。实施对应分支前由用户确认，不把建议当成已同意。

未来工程放 app/，显示名暂用“AI 减脂伙伴”，applicationId 暂用 local.foodjournal.app，首次正式安装前固定标识与签名，不在升级时随意更改。

默认只阅读代码、调用关系和差异自查；不新增或运行自动化测试，不引入测试依赖、不自行启动应用 / 浏览器做产品验收。构建、安装、真实接口检查等按后续具体授权执行，不因文档出现验收要求就认为已有执行授权。

## 2. 实施顺序

```text
M0 工程 / 环境 / 文档决策确认
 └─ M1 本地记录、子操作账本、撤销、日历
     └─ M2 Responses文字流式、主备、队列、查询
         └─ M3 图片阶段、包装标签、摘要和清理
             ├─ M4 食品资料、授权偏好和完整营养展示
             └─ M5 空值补算、关键词搜索和交互补齐
                 └─ M6 CSV、备份加密、恢复、隐私和清除
                     └─ M7 用户验收与按需打包
```

模块可以复用但默认顺序实施，不据此自动启动多代理。M1 的数据模型预留已确定的食品资料和记忆实体，不先建设通用平台。

### M0：建立工程

- 读取适用 AGENTS、当前变更与 09 的实际确认状态。
- 记录 Flutter / Dart、JDK、SDK、Gradle 和插件确切版本。
- 在 app/ 创建 Android 工程，最低API24；锁定依赖，三页和共享主题入口。
- 配置联网、系统选择器、备份排除和文件入口；不申请无关全盘权限。
- 仅在用户已经确认时落实 D01 编辑、D02 引用和 D03 模型路径；否则完成不依赖这些选择的部分。

交付：入口与依赖清楚、缺失环境记录准确，不把未构建说成可运行。

### M1：离线记录和可靠子操作

- 03 的 schema、外键、仓库、时间与单位。
- 多食物餐、独立体重、软删除、营养值和逐字段来源。
- 每子操作完整事务、前后快照、幂等回执、本地撤销和版本冲突。
- 月历双点、当日分餐 / 营养 / 全部体重、体重历史和快速新增。
- 本地手动新增、D01确认后直接编辑；名称 / 份量变化清空受影响值。
- 持续聊天、草稿、引用记录关系；删聊天不删业务记录或账本。

可观察结果：没有API也能保存、查看、纠正、删除和撤销；不同页面读同一事实，空值不变0。

### M2：文字 Responses、流式和历史查询

- Base URL规则、安全Key绑定、四模型、列表 / 手输和独立能力检查。
- text SSE分帧、UTF-8和reply增量解码、completed最终校验，不执行半截actions。
- 每请求主备各一次、超时取消、阶段与代次保护、无协议降级。
- FIFO与定向回答，独立消息失败后继续，依赖失败对象时澄清。
- 完整计划持久化、逐项校验、逐事项提交；失败仅重试未完成项。
- 一批有界只读lookup，再一次text总结，不执行模型SQL或无限循环。
- D02确认后实现长按引用，不加入右滑 / 编辑原消息重跑。

可观察结果：自然语言能记、能改、能查；文字流式但保存卡片不抢跑，部分成功和重试范围明确。

停止边界：服务不支持 Responses / SSE / 协议时明确指出能力缺口，不偷偷加入 Chat Completions。

### M3：图片识别与营养标签

- 最多3图、图文、系统选择器、方向 / EXIF / 大小 / 清晰度。
- D03确认后实现对应路径；暂定A有vision摘要持久化和text续处理。
- 包装基准、kJ/kcal、容量 / 食用量换算和不确定标签字段。
- 有效摘要落地标记清图、事务外删、启动补清；失败不长期存图。
- 追问沿用原摘要 / 时间 / action；用户“随便估”仍能合理保存。
- 不把菜单、非食物、同一盘多角度记成多餐。

可观察结果：识图内容与食用量合并，失败有手动入口；文字阶段恢复不重传已删图，相册来源不受影响。

### M4：个人资料与记忆

- 常用餐食、包装资料的不同基准；品牌、口味、规格匹配。
- 保存 / 更新确认卡、拒绝去重、资料管理和来源小标签。
- 当前餐先保存，长期资料更新单独确认；历史值保留快照。
- 已确认长期偏好、编辑删除和相关上下文注入，不自动记下所有聊天。
- 蛋白质 / 脂肪 / 碳水完整详情，估算依据按需展开。

可观察结果：同款食品可复用，份量变化正确换算，用户能控制长期保存内容。

### M5：补算、搜索与日常交互

- 正常成功后且用户队列空闲时补缺失字段，所有日期、每批10项。
- 当前NULL和版本保护；已有字段不覆盖，无法估算留原因，不递归触发。
- 消息关键词搜索、分页跳原位置；AI历史查询以最新记录为准。
- 聊天引导、滚动今日概览、三个快捷入口、长按菜单。
- 日历到聊天的对象 / 日期条可退出，明确“今天”优先。
- 停止当前、继续后续；大字体、键盘、窄屏、深浅色的实际结果在授权运行时确认。

可观察结果：离线先记，之后补原项目；查询定位可靠，日常入口不因完整功能变复杂。

### M6：导出与恢复

- 两类CSV、文本公式保护、正确空值 / 来源。
- 一致完整备份、排除Key / AI配置 / 图片 / 请求重放状态。
- 可选密码信封、成熟加密库、文件 / KDF参数边界、密码不落盘。
- 导入预览、完整校验、替换前安全副本、整库事务和失败回滚。
- data_epoch让旧请求失效，内部安全副本恢复，全部清除分项反馈。
- Android云备份 / 设备迁移排除规则、首次外部AI隐私说明。

可观察结果：可导出并恢复完整关系，错误文件不损害当前库，Key不随文件走。

### M7：验收与打包

用户自行操作下方要点并反馈；只有明确授权才由开发者运行检查、实际模型调用或设备操作。依据真实问题修复，不编造通过记录。用户要求打包后再构建、签名和交付APK，不提交凭据或私人演示数据。

## 3. 用户验收要点

以下为完成条件定义，**不是已运行结果，也不要求本轮创建测试代码**。

| 场景 | 应观察到的结果 |
| --- | --- |
| 说“一碗牛肉面” | 一餐一项，合理粗估，保存后才有成功卡 |
| 米饭 / 炒蛋 / 青菜同条输入 | 同餐逐项营养，合计正确，展开后可见 |
| 问热量 / 说准备吃 / 发菜单 | 回答或建议，不新增已吃记录 |
| 说“那碗只吃一半” | 原ID不变，份量 / 受影响营养一起更新 |
| 半数事项明确、另一项有歧义 | 明确独立项保存，另一项问，不重复已成功项 |
| 一项保存失败后只重试该项 | 成功项仍在且不增副本，本地失败不重调模型 |
| 主模型流式中断、兜底成功、主结果迟到 | 一条最终回复，未提交提案不执行，迟到响应无效 |
| 两阶段图文、文字阶段失败 | 摘要保留、原图已清，重试文字不要求重传 |
| 拍包装 / 标签 / 食用量三图 | 同一记录综合判断，按基准和实吃量计算 |
| 不清楚标签数字 | 未知 / 追问或明确普通估算，不伪造标签值 |
| 同盘多角度 / 发送第4图 | 不多记，多图限制明确，不静默丢图 |
| 视觉主备均失败 | 文字保留、可重选 / 手动记，不长存原图 |
| 132斤、66公斤、同日多次 | 换算一致，独立保留，不覆盖不画趋势 |
| 默认当天、明确昨日、跨午夜重试 | 归参考日期，不伪造时刻 |
| 从历史日AI修改、之后说今天 | 上下文可见可退出，明确日期优先 |
| 连发原记录与纠正 | FIFO，后条见前条当前值，不错改其他同名对象 |
| 停止当前而后面有独立消息 | 未提交不再保存，已提交保留，后续继续 |
| 删除消息、再开记录 | 业务记录 / 账本保留；原引用无跳转不误恢复 |
| 撤销新增 / 修改 / 删除 | 指定项逆向恢复一次，合计和双点同步 |
| 撤销目标已有后续修改 | 不覆盖后续变更，解释冲突并展示当前记录 |
| 空营养、真实0、已知热量缺蛋白质 | 空与0区分，只补缺失字段，已有值不动 |
| 补算遇新消息、后台或停止 | 用户优先、已提交保留，无无限请求 |
| 常用食物 / 包装资料同意或拒绝 | 同意才长期保存，拒绝不影响本餐且不反复问 |
| 清晰新标签与旧资料冲突 | 当前餐可用新值，更新库需确认，历史不重算 |
| 偏好临时一句和明确长期要求 | 临时不永久保存，授权偏好可管理 |
| 搜索牛肉面 / 问上次吃的日期 | 原消息可定位，AI来自当前库，查无如实说明 |
| 直接编辑 / 通用引用 | 按D01 / D02最终答案，离线和对象关联正确 |
| CSV、普通备份、加密备份 | 字段 / 空值正确，Key与原图不导出，密码错误不恢复 |
| 恢复损坏 / 高版本 / 缺引用文件 | 导入前拒绝，当前库不变，不执行文件SQL |
| 有请求时替换、再恢复安全副本 | 旧回调失效，失败回滚，误替换可恢复 |
| 清全部，外部另有备份 | 内部数据 / Key / 副本清除，外部文件不自动删 |
| 窄屏 / 大字体 / 键盘 / 深色 | 正文可读、按钮可点、无目标 / 打卡压力 |
