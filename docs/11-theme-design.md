# 11 主题视觉规范

**状态：0.1.19+20 已实施并构建、覆盖安装至 MuMu 16384。** 新主题直接替换旧浅色和深色配色，不保留旧主题选项；跟随系统 / 浅色 / 深色仍使用原设置。已接入的透明底 App 图标保持不变。实际设备范围与剩余确认见本节末尾和[实现状态](10-implementation-status.md)。

## 1. 目标和范围

采用 **现代科技感 × 石墨黑 × 柔和珊瑚橘（Modern Graphite & Soft Coral）**，同时优化浅色与深色主题。保留现有页面布局、信息顺序、组件结构、业务功能和使用习惯，以 AI伙伴页为重点，公共主题覆盖整个 App。

本规范合并用户提供的两段主题提示词，技术要求以第二段的 Flutter / Android 说明为准。实现使用现有 Flutter 原生主题体系，不引入 CSS、Tailwind、Web 主题选择器或新的 UI 框架。

实施前已在 MuMu 查看旧浅色、深色界面作为基线；README 展示替换后的真实浅深色截图，不使用生成效果图。

这是现有产品的视觉升级，不重新开发 App、不重设计信息架构。本次先完成 R17 运动记录，再以该版本的页面为基准改主题，覆盖运动卡片、表单、日历标记和相关状态。主题阶段不改变业务、数据库或路由。产品与交互继续遵守 [01 产品规格](01-product-spec.md) 和 [02 页面与交互](02-ui-and-flows.md)。

## 3. 整体视觉方向

- 现代、精致、低饱和、克制、柔和、易读，带轻科技感，保持健康记录产品的轻盈与可信赖。
- 浅色使用干净的暖中性灰白，减少大面积粉黄底色；深色使用中性石墨黑和炭灰，去除背景明显偏紫的感觉。
- 珊瑚橘只用于主要操作、品牌标记、选中状态和少量关键强调。用户气泡使用弱化的珊瑚底色，不把正文、图标、边框和所有卡片都染成主色。
- 层次主要来自背景明度差、留白和文字排版。边框只用于需要区分的区域，阴影轻微；深色普通卡片不依赖阴影区分。
- 不使用大面积高饱和橙红、霓虹、发光边框、炫目渐变或过度玻璃效果，不强制所有信息进入同一种卡片。
- 深色独立设计，不反转浅色颜色，不对所有颜色统一调暗，也不反转食物照片。避免深色中大面积纯黑与纯白的强烈对比。

1. 页面、卡片、次级区域、输入框、消息和导航要有自然的层级，不能全部合并为同一底色；也不通过突兀的色带分割顶部、正文和底部。

4. 次级文字保持易读，必要日期、说明、占位文字和错误信息不机械套用较浅的辅助色。辅助色仅在实际底色、字号和用途允许时采用。
5. 成功、警告、错误保留语义，不用品牌色替代所有状态；同时提供原有文字或图标，不只靠颜色区分。
6. 日历饮食 / 体重 / 运动标记保留可区分的分类语义、图例和无障碍描述，统一维护浅深色值；少量分类色不扩展为页面背景或另一套品牌色。

## 5. 沿用 Flutter 原生主题

### 5.1 单一主题入口

继续以 `app/lib/core/theme.dart` 和 `journalTheme(bool dark)` 为统一配置入口，保留 `MaterialApp.theme` / `darkTheme` / `themeMode` 的现有连接方式。主题值仍通过 `SettingsRepository` 传递和保存，不增加第二个主题状态、持久化键或数据库迁移。

优先使用 `ThemeData`、`ColorScheme`、`TextTheme` 及组件主题；Widget 从 `Theme.of(context)` 获取。颜色角色应成对设置背景和前景，例如 `primary` / `onPrimary`、`surface` / `onSurface`、`error` / `onError`，并检查容器色的相应前景。

不能只替换 `ColorScheme.fromSeed` 的种子色。需检查自动生成的容器色、选中背景、表面染色和状态色，避免重新引入明显的粉黄或紫色偏向。不要依赖某个组件当前碰巧没有显示的默认前景色。

### 5.2 仅抽取有共同维护价值的属性

- 通用品牌、文字、容器、边框和错误色优先放入 `ColorScheme`，页面背景通过现有 `ThemeData` 属性设置。
- 顶部栏、导航、卡片和输入框的背景优先在各自组件主题中配置，不为了不同背景再建一套主题系统。
- 用户气泡、营养次级区域、导航选中背景应按实际用途映射，避免继续用一个 `primaryContainer` 承担所有背景角色。
- 如果标准主题无法表达需要跨 Widget 共用的属性，例如成功 / 警告色、自定义消息色或日历分类色，再引入最小的 `ThemeExtension`，提供浅色 / 深色定义及 `copyWith`、`lerp`。不预先建立庞大的令牌类。
- 统一确实重复使用的圆角等常量，不把所有局部间距、尺寸和样式都抽象成令牌。

### 5.3 组件主题与 SDK 兼容

按实际使用情况配置 `AppBarTheme`、卡片主题、`InputDecorationTheme`、`NavigationBarThemeData`、`IconThemeData`、`FilledButtonThemeData`、`OutlinedButtonThemeData` 和文字按钮主题。必要时补齐弹窗、底部面板、菜单、下拉框、提示条、选择器及进度组件主题。

当前源码使用 `CardTheme`，项目文档记录 Flutter 3.19.4。实施时核对实际 SDK 后使用相应版本的 API，包括按钮状态属性；不直接复制新版 `CardThemeData` 等可能不兼容的写法，不为适配示例升级 Flutter 或依赖。

交互状态覆盖普通、按压、聚焦、禁用、加载、选中，以及平台实际支持的悬停。Android 触控优先，不能为了悬停效果改变点击、焦点或禁用语义。

## 6. 重点页面与组件

### 6.1 顶部栏与固定概览

- 保留“AI伙伴”、原有 Material 品牌图标和搜索入口；品牌图标可用珊瑚色，标题保持清晰稳重，不添加装饰或新操作。
- 保留搜索的点击区域、事件和导航。顶部背景与内容柔和衔接，不增加突兀色带。
- 今日概览及旁边等高的“今日分析”固定在聊天区上方；下方消息独立滚动，不改成覆盖消息的悬浮层。
- 用餐次数、加餐次数、已记录约多少热量、待估算提示和点击进入今天日历均保留。突出热量数值，弱化说明，不改成全天实际摄入。
- 不新增没有实际数据来源的指标、图表、进度条或固定演示数字。

### 6.2 概览旁的今日分析

- 置顶区不再显示“记录饮食 / 记录体重”；聊天与记录页的相关新增入口保留。“今日分析”保留文字、图标与原发送动作。
- 概览占剩余主要宽度，右侧分析按钮宽 96dp，通过内容测量与卡片等高，间隔 8dp、页边距 16dp，不固定高度。
- 分析按钮沿用主题的轻量描边按钮，图标在上、文字在下；不额外使用饱和背景、独立运动配色或缩字。
- 窄屏与字体放大时保持文字可读，不截断标签、不挤压图标、不横向溢出。必要调整限定在局部布局属性。

### 6.3 消息、操作上下文与结果反馈

- 用户在右、AI 在左，用户消息为弱珊瑚背景，AI 消息为中性内容背景，长回复保持易读。
- 保留用户原文、模型自然回复、保存回执和更新后的记录卡，区分正文、日期 / 引用上下文、处理状态和操作结果；不能靠隐藏内容制造简洁。
- 保留指定日期 / 记录标记、引用快照、点击返回记录或日期、长按菜单、搜索定位及定位高亮。高亮不与成功、错误或普通用户气泡混淆。
- 不改消息顺序、流式输出、队列、重试 / 停止、识图预估进度、加载与失败恢复，不改分页、离屏状态保留和新消息跟随规则。
- 保留“有新消息 · 查看最新”等真实状态入口，不用静态截图文字替代动态内容。

### 6.4 饮食、运动与体重记录卡

- 保留真实餐名、食物数量、保存状态、热量、食物名称、日期时间、待估算提示和逐食物营养；热量数值作为饮食卡主要视觉焦点。
- 保留展开明细、查看详情、AI 修改、条件满足时的撤销及既有删除 / 确认 / 版本保护逻辑。不因截图恰有撤销按钮就让所有卡片无条件显示。
- 成功图标从统一语义色取值，不在 Widget 内保留独立绿色常量；未保存时不能提前显示成功。
- 统一操作区按钮、间距和触控区域，窄屏继续允许现有换行。长食物名称不遮住操作。
- 保留食物明细左对齐、展开状态及实际记录更新，避免因主题重建导致折叠丢失、加载占位跳动、图标错位或颜色闪烁。
- 体重卡与体重历史保持单位、日期 / 时段、多次记录和原有入口，不顺带增加趋势、目标或净热量等产品能力。
- 运动卡保留名称、已知时长 / 距离 / 强度 / 消耗及未知状态，独立汇总，不抵扣饮食。详情、可选补充、编辑表单、删除 / 撤销和版本条件保持运动阶段实现；使用公共卡片、成功状态、输入框和按钮主题。

### 6.5 输入与发送

- 输入框有独立、低调的背景；深色不做成纯黑凹槽。分别处理输入文字、占位文字、焦点、禁用和错误状态。
- 发送按钮使用柔和珊瑚强调及清晰前景，保留发送中禁用等原有状态与事件，不因视觉调整新增发送条件。
- 保留拍照 / 相册、最多三张图、缩略图移除和大图预览、草稿、引用与操作上下文的关闭入口。
- 保留一至五行输入、多行换行不发送、输入焦点、键盘处理和现有输入区间距，不改变文字控制器与消息更新机制。
- 检查 `SafeArea`、软键盘、输入区和底部导航的关系，避免遮挡发送按钮或消息；不通过固定屏幕高度解决问题。

### 6.6 导航与其他交互组件

- 底部三个入口保持原图标、顺序、只显示图标的方式、无障碍名称与点击行为。中性导航底色配轻量选中背景，选中图标可用珊瑚色，未选中项用清晰中性色。
- 不让整条导航染成主色，也不改变 `IndexedStack`、页面状态保留或子页面返回逻辑。
- 将主题一致性检查延伸到“我的记录”“我的”、记录编辑、食品资料、AI 设置、数据管理，以及弹窗、底部面板、菜单、下拉框、日期 / 时间选择器和提示条。
- 加载、空状态、禁用、异常和恢复入口在两套主题下均清晰可见，不仅修改正常状态的主容器。

## 7. 尺寸、文字与适配

优先保留现有体系，不为套用提示词中的通用范围而批量改尺寸或缩小文字。

- 沿用系统中文字体和 Material 图标，不引入网络字体、新图标库或视觉依赖。
- 正文以现有 16sp、辅助文字 14sp 为基准；标题参考 20–24sp、主要数值 24–28sp，结合原组件层级局部调整。长内容保持可读，不靠缩字塞入。
- 保留 4 / 8 / 12 / 16 / 24dp 间距体系及 16dp 页边距；普通卡片圆角以现有 20dp 为基准，输入框 16–20dp、小型按钮 12–16dp 仅作校准范围，圆角按用途分层。
- 交互区域保持至少 48dp，不因通用提示词的 40–44px 参考值降低现有 Android 触控标准。
- 普通卡片以零或极轻阴影为主，深色普通卡片不加浅色阴影；不对每张卡片同时加明显边框和阴影。
- 保留现有响应式规则，不写死截图宽高，不新增无必要的绝对定位；宽屏延续现有对齐和内容宽度，不变成后台布局。
- 重点检查 320dp 等窄屏、常见手机宽度和现有宽屏布局，以及系统字体放大、长回复、长食物名称、较大数值的换行。
- 动效沿用现有克制节奏，必要时参考 150–250ms，尊重减少动态效果设置，不新增干扰输入、滚动或卡片展开的动画。
