# 02 页面与交互

## 1. 页面结构

```text
AI伙伴（默认）
  聊天式引导、今日概览、快捷入口、持续聊天
  搜索 → 结果 → 原消息
  保存卡片 → 明细 / 依据 / 修改 / 撤销
  失败 → 重试未完成项 / 手动记录
我的记录
  月历 → 当日饮食、营养、运动及全部体重
  详情 → AI修改 / 删除 / 撤销 / 更多中的直接编辑
  体重历史、手动新增
我的
  AI接口与模型 / 思考强度、单位、外观
  食品资料库、AI记忆
  CSV / 完整备份 / 恢复、清除数据、信息
```

三个主入口只显示图标，保留选中状态和无障碍名称，不扩展成五个标签；D01–D03 已确认选择统一见 09。

## 2. 首次使用与首页

首次使用，在本地欢迎消息中简短介绍文字 / 图片记录、日历、体重，提供斤 / 公斤及跳过。不依赖已配置 AI，不强制年龄、身高、性别或目标。未配置可进 AI 设置，离线手动功能可用。

标题“AI伙伴”，抽象闪光标记，右侧只保留搜索，不设跳到顶部按钮或更多菜单；AI 配置从“我的”进入，手动记饮食从“我的记录”或失败卡进入。标题栏上方不额外留白，标题下方留 8dp 后固定显示今日概览和记录饮食 / 记录体重 / 今日分析三个快捷入口，不显示问候标语，不参与聊天滚动。三个按钮等宽居中、间隔 8dp，在页面两侧 16dp 留白内铺满，每个最多 180dp，宽屏不继续拉长。下方聊天区独立上翻、分页和定位最新；查看历史时顶部仍显示当天统计。概览卡点击进入今天日历。

记录饮食聚焦输入，不提交空记录；体重打开快速录入，也可直接说；今日分析主动提交总结今天已记录内容的请求，不定时弹出。

概览示例 `2 餐 · 已记录约 1150 kcal`，有缺失时注明待估算数量，点击去今天日历。不要改成全天实际摄入。

## 3. 聊天与输入

```text
AI伙伴                                   搜索
[今日概览 / 快捷入口：固定顶部]
                10 月 19 日
                       午饭吃了一碗牛肉面
✦ 正在估算…                         [停止]
  收到，我按常见份量帮你整理。
  ┌ 午餐 · 牛肉面           ✓ 已保存 ┐
  │ 约 650 kcal           今天 12:30 │
  │ 展开明细      AI修改       撤销  │
  └───────────────────────────────┘
[操作10月15日的午餐 ×] / [引用摘要 ×]
[+] [说说刚刚吃了什么……        ] [发送]
[闪光图标]              [日历图标]             [个人图标]
```

- 用户右、AI 左，跨日有分隔。首次最近 50 条，向上分页；模型上下文不跟随界面全量加载。
- 从日历或记录带入的范围在发送后的用户气泡顶部保留，点击回原日期或记录。引用原话同时显示原日期；另选日期时清楚区分本句范围与引用原话的日期，重开、搜索定位和备份恢复后仍能辨认。
- 已在底部时跟随新消息，读旧内容时只提示“有新消息”。输入区上方留 12dp、下方留 16dp，发送按钮与输入框之间保留 12dp；键盘打开仍能用输入和主要按钮，多行换行不自动发送。
- 用户开始拖拽或滚轮上翻即暂停跟随，已排入的底部跳转也不得打断手势；回到最新后恢复。历史分页按固定分界点向上扩展，不用估算总高度补偿偏移；已加载卡片离屏后保留展开和读取状态。新消息按钮覆盖在列表上，不挤占列表高度。
- 发送先本地保存并显示“等待处理”，可继续发，前台单任务执行。取消未开始消息只影响这一条。
- “+”只有拍照 / 相册，不让人选照片类型。失败卡和“我的记录”另有手动记录入口。
- 文字或图片至少一项；最多 3 图，发送前缩略图可移除，第四张明确提示，不静默替换。已发送消息显示 80dp 压缩缩略图，点击打开可缩放的大图；点击图片或空白处均返回，拖动 / 缩放不触发单击退出。预览随聊天删除，不进备份。
- 防连点作用同一次提交，不禁用后续正常发送。停止按钮与发送独立，不清输入草稿。

### 流式与状态

真实状态包括排队、识图、整理回复、查询记录、保存本地、待补充、待确认、已完成、部分完成、失败、已停止。不模拟模型内部步骤。

图片请求先显示“准备图片”，随后按请求体实际字节显示“上传图片”、百分比和“已发送 / 总量 · 本机发送进度”。每次模型重试都重新上传并重置该百分比；100%表示本机已将请求交给传输层，不代表服务端收齐。

请求发完后显示“等待识别结果”，再开始两分钟减速至95%的“预估进度”，超过两分钟提示“这次识别貌似有点长，请耐心等待。”。聊天同轮主备共享首次发完后的等待起点，食品表单每次尝试重新计等待时间；上传期间不显示识别预估。完成、失败或停止后移除。等待百分比不参与真实超时、主备切换或保存判断。

自然语言在“生成中 / 尚未保存”气泡里增量显示，不显示协议 JSON 或原始标签解析。接口公开返回的 think 单独展示：思考时展开并流式追加，正文开始时自动折叠，点击标题可再展开；文字为灰色、13px 斜体，展开区最多220dp，区域内可滚动，思考期间跟随最新内容。已保存消息默认折叠思考内容，正文与客户端回执分别保留，不用回执覆盖回复。搜索定位中的原消息重试后也刷新正文、思考和卡片，不退出历史位置。

中断文本标记未完成，同模型重试或兜底的完整结果替换同一回复，不拼接不同尝试的回答。按 D10 显示当前模型角色与尝试次数，例如“正在重试文字主模型（2/2）”；主模型两次失败才切换备用，并显示失败原因。任一次成功或用户停止后不再继续尝试。

所有聊天折叠区域共用紧凑、无边框和无上下分割线的标题行，小箭头紧邻标题，整行保留48dp点击热区，展开后直接放内容，不嵌套面板。think正文点击也能收起，拖动仍滚动内容。折叠交互暂停自动跟随，按标题的可见位置补偿高度变化，不用动画反复挤动列表。失败时保留最后一次已收到的自然回复，小字仅给出实际保存状态和错误；旧回执中夹带的正文只显示一次。

失败项保留重试，后续独立消息继续。问题卡与上一块内容间隔 8dp，有“回答这个问题”入口；关联原事项后才解释答案，不能把答案新记一餐。若后续消息依赖未完成对象，先澄清。

### 长按、纠正与引用

菜单：复制文字、纠正关联记录、删除聊天、引用回复。输入框上方显示可移除引用摘要，不加右滑，不支持编辑原消息后自动重跑记账。

删除聊天说明不删饮食 / 体重。引用源删除后保留必要摘要、禁用原消息跳转，不靠引用恢复已删除记录。普通无记录消息不展示误导性的“纠正记录”。

## 4. 记录卡与详情

卡片是 APP 固定组件：餐名、食物摘要、约 N kcal、日期时间、保存标记；明细、AI 修改、撤销。多项操作分别展示，未保存项没有成功勾号。

展开逐食物份量和营养，每项占满可用宽度并保持同一左边界；热量突出，蛋白质 / 脂肪 / 碳水为辅助。详情另有来源小标签、折叠估算依据，显示当时保存内容。卡片查当前记录，修改后同步；删除后显示已删除。

撤销针对具体操作，不猜上一条聊天。删除确认后可撤销；详情提供最近相关操作撤销入口，不做完整版本树。之后已修改时说明不能直接撤销，并打开当前记录，不能覆盖新内容。

## 5. 日历和体重

月历默认当月今天，周一开始，上月 / 下月 / 回今天，支持跨年。饮食、体重、运动分别显示分类点，同日可并存。今天、选中、标记层级不同，配文字图例和无障碍描述；色值按 11 统一维护。

当日顺序：日期、已记录热量、三格营养概览、分餐食物、运动与独立汇总、全部体重。每个营养字段独立提示缺失，只显示有内容餐别；空日“这一天没有记录，没关系”，不做漏打卡 / 缺餐警告。

餐详情主要是 AI 修改、删除、撤销；更多中保留直接编辑。AI 修改带真实 ID、日期、当前值进入聊天，上方上下文条可退出；仅浏览历史日不改变聊天归属。

体重历史：最近一次大数字、日期 / 时间、斤 / kg 切换、全部列表、快速录入。不画趋势、日均值。当天多次全部列出，只有时段或日期的测量按录入顺序单列，不能只留末次。日期后显示具体时间或“上午 / 下午”等时段，没有时间时只显示日期。

## 6. 手动表单与直接编辑

饮食名称必填，份量、热量、三种营养素、备注可空；日期、时间和四餐别。新增时默认当前时间，仍可调整或清空；编辑时保留原时间，包括上午 / 下午等时段。默认名称 / 份量 / 热量，营养与备注收“更多”。可添加食物，一餐完整提交。

失败只预填原文字，不偷偷解析成事实。手动完成标“已手动记录”，隐藏可能重复新增的整条 AI 重跑；缺失营养仍待补算。

改名称 / 份量清空受影响营养并提示确认或留空，改日期 / 餐别不清。用户填写值标 user；版本冲突提示刷新。表单未保存退出询问，保存中防重复。

体重数值必填，单位和日期；新增时默认当前时间，可调整或清空，编辑时保留原时间。单位切换同步换算，不把 66 公斤变成 66 斤。

## 7. 我的与子页面

### AI 接口

固定 Responses；Base URL、可显隐 Key、模型列表、可搜索选择 / 手输。文字主模型必填，图片主模型在需要识图时填写，两个兜底可留空并默认收在展开项中；旧配置保留已有值。每个角色独立选择思考强度，默认跟随服务端，未指定时不发送 reasoning.effort。另有默认关闭的“请求思考摘要”，开启后聊天及能力检查请求添加 reasoning.summary=auto，仅适用于支持该参数的接口；接口主动返回的 think 不受开关限制。列表失败不清已选值，不凭名称判断视觉能力。

实际连接检查可能计费，点击前说明首次失败会自动重试一次；仅检查已填写的模型，沿用各自思考强度，每个受检模型最多两次并分别显示结果，不用兜底掩盖主失败。图片检查用非私人内置图，不上传用户照片，不写记录或触发补算。

### 食品资料库

列表可搜索名称 / 品牌，区分常用餐食和包装资料。详情含别名、口味规格、默认份量或营养基准、四营养、来源，可编辑 / 删除。日常 AI 自动查用，不要求每餐选择条目。

拍照成功后别名字段可填入AI联想的简称，例如“零度可乐、零度、无糖可乐”，用户可修改，人工保存后才生效。识别模态框与聊天共用上传百分比和识别等待两个阶段，不把发送耗时显示成模型识别耗时。

添加食品资料右上角有“AI 拍照识别”，先检查配置，再打开相机；回到当前表单显示小图，可移除或继续补拍，最多3张同一食品的照片。点击“开始识别”才调用图片模型，已有表单内容先确认替换。识别模态框显示预估进度和明确停止入口，遮罩和返回不能退出，表单暂不可编辑；完成后留在表单，自动填入名称、规格、基准、四营养及备注，Tips提示点击“保存资料”才入库。配料、过敏原等可编辑备注保存于source_json.remarks。未配置 AI 或相机不可用仍可手填，未知字段留空，基准与包装规格分开，kJ由客户端换算。照片和表单草稿在相机进程重建后恢复到添加页，不进入聊天、不自动重发识别；保存或放弃后清理照片，不进备份。

保存建议卡：摘要、保存 / 暂不保存。更新卡：同基准旧值 / 新值并排，单独确认长期更新。拒绝不影响本餐，也不反复建议同一资料。

### AI 记忆

已确认偏好 / 交流习惯列表，可编辑 / 删除，有空状态。临时聊天不擅自归为长期偏好。单位设置只有一个权威来源，不在记忆列表另造冲突的单位。

### 外观和数据

- 跟随系统 / 浅色 / 深色，默认跟随系统；体重单位斤 / 公斤。
- CSV 饮食 / 体重 / 运动分别导出，说明它不用于完整恢复。
- 完整备份可选密码，输入两次；不保存密码，遗忘无法解密。无密码时明确是私人明文文件。
- 恢复先解密、预览日期和数量，确认替换、不合并、AI 配置不变。安全副本恢复入口单列。
- 清除全部放末尾，说明记录、聊天、资料、记忆、设置、Key、图片和内部安全副本都会删除，外部导出不会自动删除。

## 8. 补算与失败

补算不占输入，可停止；按实际更新项目数提示完成，不把只补一种营养说成全部完整。新消息优先，后台不发新批次。

错误区分配置、授权、模型、无法识图、本地未保存、版本冲突。给简短原因与入口，不显示 Key、原请求或堆栈。识图成功文字阶段失败显示“图片已识别，可重试记录”，直接复用摘要，不要求重选图片。

## 9. 视觉规范

采用“现代科技感 × 石墨黑 × 柔和珊瑚橘”。浅色使用干净的暖中性灰白，深色使用中性石墨与炭灰，珊瑚橘用于主要操作、品牌标记和选中状态。完整色值、Flutter 语义令牌、组件要求和实施验收统一见 [11 主题视觉规范](11-theme-design.md)，本节不另存一套调色表。当前为文档规范，源码和 APK 尚未按新主题更新。

同时设计浅色与深色，保留现有布局、信息和全部交互；不把所有区域染成主色，不用大面积阴影或所有卡片描边制造层次。按钮背景与前景成组核对可读性，不机械使用白字。日历分类标记保留原有区别及图例，按主题统一维护。

系统中文字体，正文 16sp、辅助 14sp、标题 20–24sp、主数值 24–28sp；间距 4 / 8 / 12 / 16 / 24dp，页边距 16dp，圆角 16–20dp，触控至少 48dp。只对真实分组用卡片。

Material 图标保持一致，emoji 只少量用于聊天。动效 150–250ms、尊重减弱动画。适应大字体、窄屏、屏幕阅读器、键盘、底部手势区。后续实施时按 11 分别检查两套主题的实际显示与交互。

## 10. 运动记录（R17）

混合饮食 / 运动输入仍从 AI伙伴发送，分别显示保存卡片；运动在“我的记录”查看，不增加底部标签和首页快捷按钮。输入提示包含饮食与运动。

- 聊天按事项展示饮食卡和运动卡。运动卡突出运动名称，按实际已知内容显示日期时间、时长和消耗；未知不显示为 0，估算消耗明确标“约”。成功标记仍以本地实际保存为准。
- 信息不完整先保存，例如游泳的时长与消耗暂空；可选追问有“回答这个问题 / 暂不补充”。回答作为新修改更新同一 ID，不重做新增或同条消息中的饮食。记录已修改、删除或撤销时，原问题失效，打开当前记录重新补充。
- “我的记录”选中日期后，饮食和运动分别成组，体重仍独立保留；饮食热量和运动消耗分别汇总，不自动生成净值。
- 详情沿用 AI 修改、删除、撤销及更多中的直接编辑；手动表单只要求名称，时长、距离、强度、消耗与备注可空，日期时间沿用现有组件。修改影响 AI 消耗的参数时清空原估算并提示。
- 月历增加运动点与图例、无障碍说明；选中日按饮食、运动、体重分组。日运动汇总分别统计次数、已知时长、已知消耗与缺失数，不改变饮食营养或餐数，不计算净值。分类色统一从主题获取。
