# 02 页面与交互

## 1. 页面结构

```text
AI 教练（默认）
  聊天式引导、今日概览、快捷入口、持续聊天
  搜索 → 结果 → 原消息
  保存卡片 → 明细 / 依据 / 修改 / 撤销
  失败 → 重试未完成项 / 手动记录
我的记录
  月历 → 当日饮食、营养和全部体重
  详情 → AI修改 / 删除 / 撤销 / 更多中的直接编辑（D01暂定）
  体重历史、手动新增
我的
  AI接口与四模型、单位、外观
  食品资料库、AI记忆
  CSV / 完整备份 / 恢复、清除数据、信息
```

三个主入口不扩展成五个标签，D01–D03 暂定说明统一见 09。

## 2. 首次使用与首页

首次使用，在本地欢迎消息中简短介绍文字 / 图片记录、日历、体重，提供斤 / 公斤及跳过。不依赖已配置 AI，不强制年龄、身高、性别或目标。未配置可进 AI 设置，离线手动功能可用。

标题“AI 教练”，抽象闪光标记，右侧搜索 / 更多。内容区有简短问候、今日概览和记录饮食 / 记录体重 / 今日分析快捷入口，随内容滚走，不常驻挤压聊天。打开持续聊天定位最新，顶部轻入口可返回查看今日概览。

记录饮食聚焦输入，不提交空记录；体重打开快速录入，也可直接说；今日分析主动提交总结今天已记录内容的请求，不定时弹出。

概览示例 `2 餐 · 已记录约 1150 kcal`，有缺失时注明待估算数量，点击去今天日历。不要改成全天实际摄入。

## 3. 聊天与输入

```text
AI 教练                              搜索  更多
[今日概览 / 快捷入口：可随内容滚走]
                10 月 19 日
                       午饭吃了一碗牛肉面
✦ 正在估算…                         [停止]
  收到，我按常见份量帮你整理。
  ┌ 午餐 · 牛肉面           ✓ 已保存 ┐
  │ 约 650 kcal           今天 12:30 │
  │ 展开明细      AI修改       撤销  │
  └───────────────────────────────┘
[操作10月15日的午餐 ×] / [引用摘要 ×]
[+] [说说刚刚吃了什么……        ] [发送]
AI教练                  我的记录               我的
```

- 用户右、AI 左，跨日有分隔。首次最近 50 条，向上分页；模型上下文不跟随界面全量加载。
- 已在底部时跟随新消息，读旧内容时只提示“有新消息”。键盘打开仍能用输入和主要按钮，多行换行不自动发送。
- 发送先本地保存并显示“等待处理”，可继续发，前台单任务执行。取消未开始消息只影响这一条。
- “+”只有拍照 / 相册，不让人选照片类型。失败卡、更多和日历另有手动记录入口。
- 文字或图片至少一项；最多 3 图，缩略图可移除，第四张明确提示，不静默替换。
- 防连点作用同一次提交，不禁用后续正常发送。停止按钮与发送独立，不清输入草稿。

### 流式与状态

真实状态包括排队、识图、整理回复、查询记录、保存本地、待补充、待确认、已完成、部分完成、失败、已停止。没有阶段证据时不模拟模型内部步骤、百分比。

自然语言在“生成中 / 尚未保存”气泡里增量显示，不显示协议 JSON、推理或原始标签解析。完成提交后按真实回执定稿并生成卡片。中断文本标记未完成，兜底完整结果替换同一回复，不拼两份回答。

失败项保留重试，后续独立消息继续。问题卡有“回答这个问题”入口；关联原事项后才解释答案，不能把答案新记一餐。若后续消息依赖未完成对象，先澄清。

### 长按、纠正与引用

菜单：复制文字、纠正关联记录、删除聊天。D02 暂加引用回复：输入框上方显示可移除引用摘要，不加右滑，不支持编辑原消息后自动重跑记账。

删除聊天说明不删饮食 / 体重。引用源删除后保留必要摘要、禁用原消息跳转，不靠引用恢复已删除记录。普通无记录消息不展示误导性的“纠正记录”。

## 4. 记录卡与详情

卡片是 APP 固定组件：餐名、食物摘要、约 N kcal、日期时间、保存标记；明细、AI 修改、撤销。多项操作分别展示，未保存项没有成功勾号。

展开逐食物份量和营养，热量突出，蛋白质 / 脂肪 / 碳水为辅助。详情另有来源小标签、折叠估算依据，显示当时保存内容。卡片查当前记录，修改后同步；删除后显示已删除。

撤销针对具体操作，不猜上一条聊天。删除确认后可撤销；详情提供最近相关操作撤销入口，不做完整版本树。之后已修改时说明不能直接撤销，并打开当前记录，不能覆盖新内容。

## 5. 日历和体重

月历默认当月今天，周一开始，上月 / 下月 / 回今天，支持跨年。橙点饮食、紫点体重，有二者显示双点。今天、选中、标记层级不同，配文字图例和无障碍描述。

当日顺序：日期、已记录热量、三格营养概览、分餐食物、全部体重。每个营养字段独立提示缺失，只显示有内容餐别；空日“这一天没有记录，没关系”，不做漏打卡 / 缺餐警告。

餐详情主要是 AI 修改、删除、撤销；D01 暂在更多保留直接编辑。AI 修改带真实 ID、日期、当前值进入聊天，上方上下文条可退出；仅浏览历史日不改变聊天归属。

体重历史：最近一次大数字、日期 / 时间、斤 / kg 切换、全部列表、快速录入。不画趋势、日均值。当天多次全部列出，未注明时刻单列，不能只留末次。

## 6. 手动表单与直接编辑（D01 暂定）

饮食名称必填，份量、热量、三种营养素、备注可空；日期、可空时间和四餐别。默认名称 / 份量 / 热量，营养与备注收“更多”。可添加食物，一餐完整提交。

失败只预填原文字，不偷偷解析成事实。手动完成标“已手动记录”，隐藏可能重复新增的整条 AI 重跑；缺失营养仍待补算。

改名称 / 份量清空受影响营养并提示确认或留空，改日期 / 餐别不清。用户填写值标 user；版本冲突提示刷新。表单未保存退出询问，保存中防重复。

体重数值必填，单位和日期，时间可未注明。单位切换同步换算，不把 66 公斤变成 66 斤。

## 7. 我的与子页面

### AI 接口

固定 Responses；Base URL、可显隐 Key、模型列表、四角色可搜索选择 / 手输。列表失败不清已选值，不凭名称判断视觉能力。

实际连接检查可能计费，点击前说明；分别显示主备 / 文字图片结果，不用兜底掩盖主失败。图片检查用非私人内置图，不上传用户照片，不写记录或触发补算。

### 食品资料库

列表可搜索名称 / 品牌，区分常用餐食和包装资料。详情含别名、口味规格、默认份量或营养基准、四营养、来源，可编辑 / 删除。日常 AI 自动查用，不要求每餐选择条目。

保存建议卡：摘要、保存 / 暂不保存。更新卡：同基准旧值 / 新值并排，单独确认长期更新。拒绝不影响本餐，也不反复建议同一资料。

### AI 记忆

已确认偏好 / 交流习惯列表，可编辑 / 删除，有空状态。临时聊天不擅自归为长期偏好。单位设置只有一个权威来源，不在记忆列表另造冲突的单位。

### 外观和数据

- 跟随系统 / 浅色 / 深色，默认跟随系统；体重单位斤 / 公斤。
- CSV 饮食 / 体重导出，说明它不用于完整恢复。
- 完整备份可选密码，输入两次；不保存密码，遗忘无法解密。无密码时明确是私人明文文件。
- 恢复先解密、预览日期和数量，确认替换、不合并、AI 配置不变。安全副本恢复入口单列。
- 清除全部放末尾，说明记录、聊天、资料、记忆、设置、Key、图片和内部安全副本都会删除，外部导出不会自动删除。

## 8. 补算与失败

补算不占输入，可停止；按实际更新项目数提示完成，不把只补一种营养说成全部完整。新消息优先，后台不发新批次。

错误区分配置、授权、模型、无法识图、本地未保存、版本冲突。给简短原因与入口，不显示 Key、原请求或堆栈。识图成功文字阶段失败显示“图片已识别，可重试记录”，不要求重选已删图。

## 9. 视觉规范

| Token | 浅色 | 深色建议 |
| --- | --- | --- |
| 背景 | `#FFF8F2` | `#211E25` |
| 卡片 | `#FFFFFF` | `#302A34` |
| 蜜桃强调 | `#F29B83` | `#F4AD97` |
| 主文字 | `#35313D` | `#F4EDF2` |
| 次文字 | `#746774` | `#C6B8C5` |
| 用户气泡 | `#FCE6DF` | `#563C39` |
| 紫 / 绿辅助 | `#B7A4E8` / `#92C9B1` | 保留色相，降低底色亮度 |
| 分隔线 | `#F1E2DE` | `#514550` |

浅桃色用于底色和强调，按钮文字用深色，不照搬原型白字低对比组合。深色值为本项目设计值，不宣称源于原型。

系统中文字体，正文 16sp、辅助 14sp、标题 20–24sp、主数值 24–28sp；间距 4 / 8 / 12 / 16 / 24dp，页边距 16dp，圆角 16–20dp，触控至少 48dp。只对真实分组用卡片。

Material 图标保持一致，emoji 只少量用于聊天。动效 150–250ms、尊重减弱动画。适应大字体、窄屏、屏幕阅读器、键盘、底部手势区。实际视觉验收留给后续运行授权。
